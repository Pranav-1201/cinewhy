# Phase 2 — Grades

Scored as in a real design review. Every score cites evidence gathered this run.

## The three defects that dominate the grade

### C-1 · Vocabulary leakage — cells 20 and 30 · **methodology, P0**

`cv.fit_transform(df["review"])` runs on all 10,000 rows; `train_test_split` runs on the *next*
line. The vectorizer's 1,000-word vocabulary — and TF-IDF's IDF statistics — are learned from data
that includes the test set.

Measured, same seed, only the fit moved after the split:

| Model | as written | leak-free | delta |
|---|---|---|---|
| **BernoulliNB (BoW)** | **0.8350** | **0.8185** | **−0.0165** |
| MultinomialNB (TF-IDF) | 0.8330 | 0.8220 | −0.0110 |
| MultinomialNB (BoW) | 0.8255 | 0.8200 | −0.0055 |
| GaussianNB (BoW) | 0.7820 | 0.7805 | −0.0015 |

The headline 83.5% is inflated by 1.65 points. The report's §12 states the opposite —
*"cleanly bifurcated to prevent spatial data leakage"* and *"a pure 2,000 test vector isolated
entirely from optimization fitting calculations."* Both are false as written.

### C-2 · The declared winner is noise, and the ranking reverses · **methodology, P0**

Cell 35 selects "best model" by comparing test accuracies: 0.8350 vs 0.8330. **A 0.0020 margin.**

Measured 5-fold CV on the training split only:

| Model | CV mean ± std | folds |
|---|---|---|
| **MultinomialNB (TF-IDF)** | **0.8383 ± 0.0091** | 0.8494 0.8444 0.8281 0.8425 0.8269 |
| MultinomialNB (BoW) | 0.8293 ± 0.0126 | 0.8419 0.8362 0.8162 0.8400 0.8119 |
| BernoulliNB (BoW) | 0.8285 ± 0.0117 | 0.8362 0.8362 0.8206 0.8400 0.8094 |

The winning margin is **an order of magnitude smaller than the fold-to-fold spread**, and under
honest evaluation the notebook's champion (BernoulliNB) finishes **last of the three**. The report's
interpretation — *"BernoulliNB dominating the environment reflects a key NLP reality"* — is a
narrative built on noise, with the sign inverted.

The test set was also used for selection, so 0.8350 is not a clean generalization estimate even
before the leakage.

### C-3 · Negation is destroyed before the model sees it · **methodology, P0**

`not`, `no`, and `nor` are all in NLTK's English stoplist, and stopword removal (cell 16) runs
before anything else. Verified end to end:

```
"This movie was not good at all."  →  'movi good'
"This movie was good."             →  'movi good'

preprocessed strings identical : True
TF-IDF vectors identical       : True   (np.array_equal)
prediction for both            : 0 / 0  (negative)
```

Two reviews with opposite sentiment produce byte-identical feature vectors. The pipeline is
structurally incapable of representing negation — and it gets the *positive* review wrong.

This also falsifies the report's §18 error analysis, which claims the model sees `not`, `exact`,
`terribl` as independent unigrams and mis-weights them. It never receives `not` at all. The stated
mechanism cannot occur.

# Phase 3 — Improvement brainstorm

## Strategic direction — answered honestly first

**Who would actually use this?** Nobody, today. A sentiment API has no consumer audience, and the
assignment target — a Netflix-style recommender — cannot be built from the current data at all.

**Does an off-the-shelf model already do the core thing better?** Yes, twice over. A fine-tuned
transformer beats this on IMDB sentiment; a frontier LLM does comparably zero-shot. And
`implicit`/`LightFM`/`surprise` solve collaborative filtering better than a from-scratch build will.
Competing on either axis is a losing position.

**So what is durable?** Not the algorithm — the **evidence layer**. A recommender that justifies
each pick with aspect-level sentiment mined from real reviews, and shows the actual sentences.
That is a *trust* property, it compounds with data, and it is the thing incumbents visibly do badly
("Because you watched X" is famously uninformative).

### Three options considered

| | Direction | Assessment |
|---|---|---|
| **A** | Polish the sentiment classifier (transformer, 93%) | Honest, small, unoriginal. A weekend's work with no user. **Rejected.** |
| **B** | Standard MovieLens recommender | Solved problem, thousands of clones, no differentiation. **Rejected.** |
| **C** | **Recommender + review-grounded aspect explanations** | Uses the sentiment work as a real component, has a defensible angle, satisfies the assignment, and is genuinely usable. **Recommended.** |

**Recommendation: C — "CineWhy".** The tagline that captures the difference:

> Netflix: *"Because you watched Inception."*
> CineWhy: *"Because you consistently praise **pacing** and **endings** — and across 1,240 reviews,
> this film's pacing scores +0.71. Here are the three sentences that say so."*

Every tactical idea below serves direction C.

### The architectural facts that rule the others out

- **Vercel / Netlify serverless functions** — rejected. No persistent disk, and an unzipped bundle
  cap in the low hundreds of MB. Transformer weights plus an ANN index do not fit, and there is
  nowhere for them to survive between invocations. *(This is why the frontend goes there and the API
  does not.)*
- **Render free web service** — rejected. 512 MB RAM will not hold the model plus index, and the
  service sleeps with a long cold start.
- **Fly.io / Railway** — rejected for a *free-tier-only* constraint: both moved to trial-credit
  models rather than a standing free allowance.
- **Any GPU host** — rejected. Nothing in this design needs one, because all embedding and scoring
  happens offline.

**Alternative if the free-tier constraint ever lifts:** a single small VPS (~$5–7/mo) running the
container behind Caddy for TLS. Simpler mental model, one box to reason about, no cold starts —
at the cost of patching it yourself.

# Rules for implementing sessions

1. **One PR per plan row.** Reference the idea ID (M1, B3, F2…) in the branch and the commit.
2. **Suite green at every checkpoint.** Non-zero test count, or it is not green.
3. **Stop at phase boundaries** for review. Do not run two phases together.
4. **Commit with explicit paths.** Never `git add -A` — stray artifacts are a known hazard here.
5. **Additive checkpoints for restructures.** New code lands and passes *before* old code is removed.
   The tree never goes red.
6. **Leave uncommitted work alone.** Dirty tree at session start → say so and stop.
7. **A guard test must be watched failing** against pre-fix code before it counts as protection.
8. **Never edit a test to make a change pass.** The failing test is the finding.
9. **Fresh evidence in the same message** as any completion claim — command plus output, run this
   session. Read the count.
10. **End every session** by updating the five-line ritual in `HANDOVER.md`.

## Unresolved, handed over honestly

**H-1 · ASIN → film mapping.** Amazon Movies&TV item IDs are ASINs — a specific product edition, not
a film. Whether they map cleanly to MovieLens/TMDB is **unverified**; this audit did not attempt it.
Not a dead end, simply unexplored. Reproduce with 200 random ASINs, attempt a title match, hand-check
30, *then* design around the result.

**H-2 · Do the 418 duplicate reviews actually straddle the split?** The duplicates are measured;
their distribution across `random_state=42` is not. Cheap to check, and it must be checked before any
accuracy figure is called clean.

Neither was root-caused, so neither gets a guessed cause. Both are marked **reproduce first**.
